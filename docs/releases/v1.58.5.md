## Changelog

### Correzioni
- **Installazioni nuove**: un'utenza senza capitolo di spesa (contratto a titolo gratuito, capitolo ancora da assegnare) non si salvava, perché la prima migration creava la colonna come obbligatoria; ora è facoltativa come sulle installazioni esistenti. Trovato dai nuovi test d'integrazione su MySQL (#423).
- Date `AAAA-MM-GG` lette come giorno locale anche nei browser con un fuso a ovest di UTC: prima risultavano il giorno precedente. In Italia nessun effetto (#423).
- Query del backend riscritte con TypeORM (repository e QueryBuilder) senza cambi di comportamento: anomalie, spesa per capitolo, utenza e immobile, impegni e riconciliazione delle quote, import fatture dalla PEC, import della contabilità, fabbisogno della convenzione, storico utenze. Prima della conversione ogni modulo ha avuto i suoi test d'integrazione, che restano verdi senza cambiare i risultati attesi. Per i moduli di calcolo (anomalie, spesa, impegni e riconciliazione delle quote, import della contabilità, fabbisogno) i risultati sono stati confrontati anche su una copia del database di sviluppo e sono identici; storico utenze, import fatture e gli altri moduli sono coperti dai soli test d'integrazione (#423).
- CI: test d'integrazione su MySQL a ogni PR, test di proprietà sulle funzioni di calcolo, job pesanti saltati sulle PR di sola documentazione (#423). Nessun effetto sulle installazioni.

### Sicurezza
- Nessuna vulnerabilità corretta. Le chiamate `.query(` con SQL scritto a mano restano in pochi file `*.sql.ts`, ciascuno col motivo, e una regola ESLint bloccante in CI impedisce di aggiungerne altrove; le altre query passano dal QueryBuilder di TypeORM con parametri con nome (#423).

### Aggiornamento
- Migration `UtilityChapterNullable`, eseguita all'avvio: sulle installazioni esistenti non cambia nulla (la colonna è già facoltativa). Nessuna azione oltre a pull e up (`IMAGE_TAG=v1.58.5`).
