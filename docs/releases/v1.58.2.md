## Changelog

### Correzioni
- Release: `latest` si sposta solo al tag di versione più alto, quindi una correzione rilasciata su una versione vecchia non lo riporta indietro; il rebuild manuale di `latest` parte solo da `main` (#404).

### Sicurezza
- Caricamento delle foto: il nome del file scelto dall'utente non entra più nel percorso sul server. Prima un utente Admin o Operatore poteva, con un nome costruito apposta, scrivere e poi cancellare file fuori dalla cartella temporanea, nei volumi dell'applicazione (allegati, foto, backup, casella della contabilità) (#406).
- Caricamenti a pezzi (foto, allegati, ripristino del backup): l'identificativo del caricamento è controllato in ogni passaggio e il nome del file finale non può uscire dalla cartella (#406).
- Nuovi utenti: la password iniziale, mai comunicata ma valida per l'accesso locale, è casuale crittografica di 32 caratteri invece di 6 caratteri generati con `Math.random()` (#406).
- Contabilità (container tinn): i file della casella condivisa con l'API non sono più leggibili da altri utenti del sistema (`0o660`) (#407).
- Dipendenze: correzione automatica delle vulnerabilità con PR del bot e aggiornamento notturno dei lockfile con commit verificati (#402, #403, #408).

### Aggiornamento
- Nessuna migration e nessuna variabile nuova: `IMAGE_TAG=v1.58.2`, `docker compose pull`, `docker compose up -d` (consigliato `VERIFY_IMAGES=true`).
